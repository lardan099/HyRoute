# Обновления

## Ядро Hysteria

Обновляется отдельно от HyRoute:
- проверяются `apernet/hysteria` releases, только стабильные с тегом `app/v2.*` (совместимость —
  мажор 2);
- ассет `hysteria-windows-amd64.exe` сверяется с `hashes.txt` того же релиза и с дайджестом ассета
  из API GitHub;
- ядра лежат в `%ProgramData%\HyRoute\core\<версия>\` с защищённым DACL: SYSTEM и Administrators —
  запись, Users — чтение. Если бы они лежали в `%APPDATA%`, процесс без админских прав мог бы
  подменить exe, который HyRoute запускает с правами администратора. Владельцем папки ставится
  Administrators (владелец сохраняет WRITE_DAC при любом DACL); папку, созданную заранее не
  администратором, HyRoute не принимает; путь `%ProgramData%` берётся из `KnownFolderPath`, а не из
  переменной окружения. Папки создаются сразу с защищённым DACL (CreateDirectory с дескриптором),
  без промежутка с DACL, унаследованным от `C:\ProgramData`. `core.json` читается, только если он и
  папка `core` принадлежат Administrators/SYSTEM/TrustedInstaller; иначе обновление ядра не
  используется (работает встроенное, в разделе обновлений показывается причина). Папку `updates`,
  созданную не администратором, HyRoute при старте не очищает;
- `core.json` хранит `current`, `previous` и их SHA256; хэш сверяется перед каждым запуском;
- новое ядро проверяется запуском `hysteria.exe version`. Если `hysteria version` не ответил, ошибка
  запоминается на минуту, потом проверка повторяется; пока версия текущего ядра неизвестна,
  обновление ядра не предлагается (показывается ошибка);
- во время активного соединения переключение не происходит: оно применяется при следующем
  подключении или по кнопке «Переподключить»;
- если новое ядро не стартует (процесс сразу падает не из-за сервера), доступен откат на `previous`,
  а статус подсказывает это;
- если встроенное ядро не старше скачанного (вышла новая версия HyRoute), работает встроенное.
  Скачанные ядра удаляются при первом запуске после подтверждённого обновления HyRoute: пока
  существует `update-journal.json` (новая версия ещё не прислала сигнал «здоров»), они остаются,
  чтобы прежняя версия после отката снова их нашла. Откат на `previous`, который не новее
  встроенного, тоже приводит к встроенному; после отката на встроенное ядро кнопки отката нет.

## HyRoute

Обновляется через GitHub Releases своего репозитория. Репозиторий задаётся при сборке, `-X
main.updateRepo=owner/repo`.
- Канал Stable берёт последний релиз без `prerelease`. Канал Beta предусмотрен в модели (берёт и
  `prerelease`; prerelease-версии сравниваются по semver: beta.10 > beta.9), в UI пока скрыт.
- Релиз — это `HyRoute-<ver>-windows-amd64.zip` + `SHA256SUMS`. Пакет собирает workflow
  `release.yml` по тегу `v*`. Версию сборки и имя пакета workflow задаёт явно (`HYROUTE_VERSION` =
  пушнутый тег); `build.ps1` и `package.ps1` падают, если HEAD не этот тег. Локально без переменной
  версия по-прежнему берётся из `git describe`.
- **Ход обновления:**
  1. Показать текущую и новую версию и changelog (тело релиза), кнопки «Обновить / Позже».
  2. Скачать в `%ProgramData%\HyRoute\updates\<ver>\`, сверить SHA256 (`SHA256SUMS` + дайджест API),
     распаковать, сверить каждый файл. Если за время загрузки проверка нашла другую версию,
     скачанный пакет не предлагается: загрузку нужно повторить; вторая загрузка параллельно не
     запускается.
  3. Штатно остановиться: снять фильтры, закрыть WinDivert, остановить все Hysteria.
  4. Запустить **отдельный** `hyroute-updater.exe` из новой версии, скопированный в staging, и
     выйти.
- **Работа updater'а:**
  1. Ждёт завершения PID HyRoute без лимита и заново сверяет хэши. Если exe переименован, HyRoute
     передаёт `--exe`, и заменяется именно этот файл.
  2. Каждый заменяемый файл: `X` → `X.old`, новый копируется на место. Любая ошибка — откат всех
     `.old`.
  3. Запускает новый HyRoute с `--updated-from <старая версия>` и ждёт сигнала «здоров» (именованное
     событие) до 3 минут. Нет сигнала или процесс упал — откат и запуск старой версии (updater
     передаёт ей `--update-failed <целевая версия>`); если до обновления HyRoute был подключён, она
     получает `--reconnect` и подключается снова. «Подключаться сразу после запуска» после отката
     тоже работает.
  4. `.old` удаляются только после сигнала.
- **Ограничения:**
  - Целостность проверяется по SHA256. Подпись релизов своим ключом (ed25519) — следующий шаг, если
    понадобится защита от компрометации аккаунта GitHub.
  - **Приватный репозиторий:** API GitHub без токена релизы не отдаёт. Для автообновления нужен
    публичный репозиторий, хотя бы отдельный `HyRoute-releases`.
  - Сборки без тега (`dev`) по умолчанию не проверяют обновления автоматически, ручная проверка
    работает.
  - У загрузок (обновления, ядро) нет общего таймаута: загрузка обрывается, только если сервер
    ничего не присылает 60 с.

- Журнал обновления (`internal/update/journal.go`): до первой замены updater записывает план (какие
  файлы заменяются, какие добавляются) в `%ProgramData%\HyRoute\update-journal.json` с fsync. Журнал
  удаляется только после сигнала «новая версия работает» (Commit) или полного отката. Если updater
  умер посередине (питание, kill), следующий запуск HyRoute без `--update-event` находит журнал,
  откатывает то, что успело замениться (файлы с `.old`, недописанные `.new`, добавленные), запускает
  восстановленный exe (с `--autostart`, если сам был запущен задачей входа) и выходит: он сам мог
  быть новым exe. Это делается, только если `%ProgramData%\HyRoute` и журнал принадлежат
  Administrators, SYSTEM или TrustedInstaller (текущему пользователю — только без разделённого
  UAC-токена; проверка до чтения файла) и `target` журнала совпадает с папкой запущенного exe: этот
  код работает с правами администратора, а папку мог создать обычный процесс. Имена в журнале —
  только простые имена файлов; поле `exe` хранит имя заменяемого exe. Запущенный exe нельзя удалить,
  но можно переименовать: он откладывается как `<имя>.<наносекунды>.bad` и удаляется при следующем
  старте; другие файлы `*.bad` в папке программы не трогаются. Журнал хранит `reconnect` (HyRoute
  был подключён до обновления), и восстановление передаёт прежней версии `--reconnect`. Updater, чей
  PID записан в журнале, считается живым, только если процесс с этим PID создан не позже `started`
  (иначе номер занял другой процесс).
- Сигнал «работает»: окно загружено и, если до обновления HyRoute был подключён (`--reconnect`),
  `Connect` вернулся успешно — драйвер открыт, фильтры стоят. Недоступный сервер откат не вызывает.
  Ожидание updater — до 3 минут, потом откат и запуск прежней версии.
