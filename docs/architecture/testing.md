# Тесты

- `packet`: checksum (известный вектор + эталонная реализация), v4/v6, IPv6 extension headers,
  фрагменты, сборка UDP-ответа, RST на SYN.
- `engine/nat`: reflect-переписывание v4/v6, двусторонний lookup, коллизия `(R, lp)`, повтор SYN,
  замена закрытой записи, FIN/RST/грейс/idle.
- `divert`: раскладка `WINDIVERT_ADDRESS` (80 байт, битовые поля), декодирование SOCKET/FLOW-данных
  и host-order адресов, разбиение батча, фильтр (исключения без `!=`), тексты ошибок, проверка
  версии.
- `attrib`: точный ключ, IPv4-mapped, неуказанный local IP, bind, закрытие только своего endpoint'а,
  уведомления, чистка, разбор таблицы TCP IP Helper и снимок (владелец, LISTEN).
- `socks5`: CONNECT с user/pass, отказ авторизации, ошибки REP, домен, отмена по контексту, UDP
  ASSOCIATE.
- `relay`: туннель end-to-end через заглушку, half-close, хвост доходит до приложения, которое
  поставило чтение на паузу; RST при Close, пока хвост не подтверждён; RST от приложения завершает
  ожидание; Close с ограниченным ожиданием обработчиков, RST при недоступном туннеле (и ничего не
  уходит в upstream), RST при ошибке SOCKS, посторонние подключения, Close с активными соединениями,
  RST при Close, отмена ожидающего dial, передача сброса на другую сторону, Direct с адреса
  приложения, запросы к forward-прокси.
- `hysteria`: URI parse/gen (мульти-порт, percent-encoding, `hy2://`, IPv6, нестандартные параметры,
  ошибки), round-trip, генерация YAML (golden files), лог-парсер и классификация ошибок, supervisor
  с фейковым hysteria (подключение, туннель, удаление конфига, backoff при auth-ошибке, секреты не
  попадают в лог).
- `procinfo`: переиспользование PID.
- `rules`: домены (exact, `*.`, `.`, регистр, trailing dot, IDN/punycode), app (name/path/glob,
  наследование, неизвестный процесс), first match, составные правила, трёхзначный Evaluate
  (DNS-имена сходятся/расходятся, ветви сходятся, правила другого приложения не создают
  неоднозначности), `EvaluateSites` (имена CNAME-цепочки — один сайт), `MayTunnel`, ошибки
  компиляции.
- `dnscache`: TTL и его ограничения, несколько имён на IP, смена IP, CNAME-цепочки, IDN, отказ от
  запросов/NXDOMAIN/мусора, DNS over TCP, лимит размера, ответ принимается только на увиденный
  запрос, сайты CNAME-цепочек, ограниченный Sweep, публичные имена ECH из HTTPS-записей, ответ через
  туннель только на туннельный запрос.
- `sniff`: настоящий ClientHello из `crypto/tls`, фрагментация по сегментам и по TLS-записям, без
  SNI, IP в SNI, ECH (внешний SNI сохраняется), мусор, обрезанные данные, HTTP Host с портом,
  IP-литералы.
- `relay` (SNIFF): SNI → Tunnel с remote DNS, Host → Direct с неизменным буфером, таймаут,
  server-first порты, Block, туннель недоступен, NO-SNIFF всегда по IP.
- `engine` (ядро, синтетические пакеты): reflect туда и обратно, Direct со счётом байт и закрытием
  по FLOW_DELETED, RST при недоступном туннеле, IPv6-блок, Block по DNS-домену, SNIFF при
  неизвестном домене и решение relay, поздняя атрибуция, таймаут, IP Helper, исключения self и
  системного DNS, посторонний inbound на relay, блок QUIC, UDP Direct, UDP-туннель end-to-end через
  SOCKS5-заглушку (ответы собираются в пакеты), drop при недоступном туннеле, истечение сессий,
  DNS-сниф → решение на уровне пакетов, `exclusion: hysteria`, DoH/DoT Dnscache, переполнение
  pending + IP Helper, повторное использование порта закрытой NAT-записи, RST при остановке движка,
  перевыбор профиля UDP-потока, фрагменты не-TCP/UDP, IPv6 AH, соединения без состояния (открытые до
  старта): Tunnel/Block → RST с seq = ACK, Direct и исключения проходят, серверная сторона входящих
  соединений проходит, домен только из DNS cache, одно чтение таблицы IP Helper на много соединений,
  ограниченная память решений; RST отражённых соединений при отказе движка, без зависания на
  блокировках; решение по ECH в `RelayDecide` (GREASE ECH, известное публичное имя), IPv6-SYN с
  доменным правилом в туннель сбрасывается сразу.
- `settings`: значения по умолчанию, неизвестные поля, перезагрузка файла, битый файл не заменяет
  правила.
- `settings`: опции движка покрывают все поля вне правил (`TestEngineOptionsCoverSettings`).
- `app` ([rules.md, «Сохранение правил и ревизии»](rules.md#сохранение-правил-и-ревизии)): ревизия и
  событие на каждую запись (`TestSettingsRevAndEvent`), отказ устаревшей копии и отсутствие ложных
  отказов после записи опций (`TestSaveSettingsRevision`), опции отдельно от правил
  (`TestSaveEngineOptions`), «Правила текстом» с ревизией, параллельные писатели, сбой записи ничего
  не меняет, в `settings.json` нет новых ключей.
- `store`: `readRegular` читает только обычный файл с одним именем в пределах лимита; жёсткая и
  символическая ссылка, папка, точка соединения (Windows, без прав администратора) отклоняются.
- `store` ([rules.md, «Профили правил»](rules.md#профили-правил)): `rulesets.json` — строгий разбор,
  профиль «новее» с сохранением байтов, отказы (версия, ID, имена, отметка, размер), только обычный
  файл, `ConfigHash`, запись пары с возвратом прежних байтов при сбое `settings.json`;
  `ReadRaw`/`WriteRaw` не следуют по ссылкам.
- `rules`: `Check` без баз правил отклоняет то же, что `Compile`, и не обращается к базам.
- `app` ([rules.md, «Профили правил»](rules.md#профили-правил)): файла нет до второго профиля;
  записи S/R/P и отметка (`TestMarkerForcesPair`); сверка при загрузке (прерванная запись, правка
  снаружи и возврат к прежним правилам, нет `settings.json`, битые файлы, профиль с ошибкой); токены
  и ревизии обоих режимов (`TestEditModeRevision`, `TestActiveRevisionRulesAt`,
  `TestEditorTokenCapturedAtOpen`); `Stopped`; отказ до `netManual`; нет компиляции под `c.mu`;
  «новее»; ссылки из неактивных профилей; параллельные переключения и правки под `-race`.
- `main`: `trayRulesetsView`, `trayPlan` — порядок вызовов systray.
- `rules`: `Registrable`/`Site`/`HostName` (публичные суффиксы, IP и короткие формы IPv4 вроде
  `1.2.3`, цифровой домен верхнего уровня, IDN, длины меток 63 и имени 253/254).
- `engine`: вид исключения (`self`/`hysteria`/`system-dns`) записывается в `Excluded`, правило
  пользователя с именем «exclusion: …» исключением не считается.
- `groups` ([servers.md, «Группы серверов»](servers.md#группы-серверов)): разбор `groups.json`
  (версия, лишние поля, границы, пустые группы и висящие ID допустимы), `ValidateEdited`, `Prune`,
  `Remap`, `MainOf`, проверка адреса пробы; `Runtime` с поддельными часами под `-race`: все
  стратегии, гистерезис, возврат на первый только после 30 с без сбоев, серии ошибок и ровно одно
  пробное соединение из 50 параллельных, `Abandon`, пересчёт после пробы без пробного соединения,
  штраф пробы только при ответе через другой сервер, `Pick.Failover`, `ResetSession`, стабильный
  выбор (`Hint.Stable`, `TestChooseStable`); `ProbeOnce` против loopback HTTP/HTTPS, отмена не
  считается отказом.
- `engine` (группы): цель правила — группа, запасной после группы, отказ с RST и счётчиком группы,
  неизвестная группа, UDP без UDP-сервера, sticky по одному сайту в `decide` и `RelayDecide`,
  IPv6-блок ничего не фиксирует, `Abandon` при коллизии NAT и упавшем сервере, двухфазное разрешение
  цепочки, без групп решения прежние (`TestNoGroupsUnchanged`).
- `tunnels`: `OnDial` только у рабочих конечных точек (не у проверок, не отменённые, не `Quiet`),
  `OnHealth` только у рабочих.
- `app` (группы): запуск серверов только используемых групп, основная группа (profiles.json не
  трогается), одна битая группа не мешает другим, подписка не опустошает используемую группу,
  запреты удаления, битые `profiles.json`/`groups.json`, «Проверить» у группы (одна проверка на
  группу, бюджет, нехватка адресов), прокси через группу, «Проверить адрес», проверка сервера не
  портит его серию ошибок, `groups.json` не создаётся без групп, группы в «Правилах текстом».
- `rules` (порты): разбор и канонизация (таблица, общая с `parsePorts` в UI), JSON: строка v1.2.0 и
  массив строк и чисел, запись строкой v1.2.0, слияние диапазонов, границы совпадения, порт 0,
  покрытие и пересечение, порты выключенных правил, правило только из портов и его имя, трёхзначная
  оценка с портом, Explain (шаг порта, заметка «Порт не указан», «Блокировка QUIC» совпадает с
  `Set.Evaluate`), lint (перекрытие по портам, info о локальных UDP-серверах, QUIC).
- `app` (порты): опции портов в «Правилах текстом», правило `* -> … | tcp 22`, round-trip с портами
  и обезвреживание неверных (ошибка только в своей строке), порт в «Проверить адрес» (из адреса, из
  ссылки, поле важнее), QUIC по настройкам, «Списки» для TCP 443, конвертер ACL (порты, `all` с
  портом, пропуск перенаправлений, совпадение с `parseProtoPort` Hysteria). DNS в этих тестах не
  запрашивается (`lookupIP`).
- `packet`: сборка фрагментов (любой порядок, повторы, перекрытия, длина UDP, края размера
  IPv4/IPv6, опции IPv4, fuzz), нарезка `FragmentIP` и обратная сборка.
- `socks5`: предел Hysteria `MaxUDPPayload` (таблица адресов, совпадение с байтами на проводе,
  IPv4-mapped и зона, нижняя граница).
- `engine`: сборка UDP-фрагментов в туннель, исходные фрагменты для Direct (и после ожидания
  владельца), повтор ID между потоками, нагрузка на таблицу фрагментов, паника в сборке и при
  повторе, самовосстановление счётчиков, предел Hysteria, туннель недоступен, неполные и
  перекрывающиеся фрагменты, бюджеты памяти (сборка и очередь ожидания владельца), истечение записи
  при поиске, первый фрагмент без портов, DNS-запросы из фрагментов, параллельные циклы пакетов.
- `flows`: `tooBig` и производный исход «dropped: larger than Hysteria carries».
- `rules` (правило из соединения): `Place`/`Winner`/`PlaceRule` (цепочка CNAME, соседи CDN,
  `pending` против неизвестной категории, неизвестный протокол), `TestWinnerAgreesWithEngine` (2000
  случайных наборов против `Set`), `Intersects` (симметричность), `SameMatch`, `OverriddenBy`,
  `Shadowed`, `Narrowed`, `CatchesName`.
- `app` (правило из соединения): запись потока важнее данных WebView, перегруппировка по живому
  кэшу, области меню (сайт, адрес, IP, CDN-имя, IDN), ECH, строки DNS-запросов, вставка над решающим
  правилом, изменение на месте только при `Place == Winner`, редактор, отказы без записи, отмена
  (изменено, удалено, смена профиля, сбой записи, ёмкость 20, параллельно), `clearConnUndo`,
  параллельные записи, ключи `settings.json` v1.0.0.
- `flows`/`engine`/`relay`: `Parents`, `Sites` и `ECH` в записи, `Lookup`, `CapSites`.
- `app` ([servers.md, «Идентичность серверов и
  подписки»](servers.md#идентичность-серверов-и-подписки), информация подписки): разбор
  `subscription-userinfo` (регистр, разделители, дубли, дроби, отрицательные, переполнение,
  миллисекунды, длина) и fuzz-тесты разбора и представления (без паники и переполнения, проценты в
  пределах, год не больше 9999); размеры с отбрасыванием («9.9 ГБ», не «10.0 ГБ»); тексты и
  склонения; ключ предупреждения; политика предупреждений (автообновление выключено, время
  неизвестно, старые цифры с датой); заголовки через настоящий `httpFetch` и `httptest` на 127.0.0.1
  (очистка названия, лимиты, 64 КБ заголовков, ответ 403 не читается, ответ 200 без списка сохраняет
  цифры); откат датирует цифры прежним `lastUpdate`; `safeLink` и подменённая ссылка в файле; ссылка
  поддержки не попадает в redactor и диагностику; без новых данных ничего не пишется.
- `store`: `infoAt` и `supportUrl` переживают запись и чтение и не пишутся, пока не нужны; файл
  1.0.0 читается, новый файл читается структурой 1.0.0.
- `dnspolicy` ([dns.md, «DNS-политики»](dns.md#dns-политики)): разбор адреса своего сервера (таблица
  сообщений карточки), пресеты, `Validate`/`Active`, списки DoH (без частных диапазонов, суффиксы),
  локальные имена и имена роутеров, классификатор: имена серверов и служебные до всего, канарейка и
  ECH только с опциями, правила с программой и протоколом «условно» (VPN побеждает, блок только если
  все «блок»), правило «Напрямую» по адресу выше, локальные адресные правила не считаются,
  `ForSecondary`.
- `rules`: `EvaluateName` (условия программы, протокола и портов, адресные правила в `Alt`,
  `AddrLocal`), `SrcQuery`.
- `dnsproxy` ([dns.md, «DNS-политики»](dns.md#dns-политики)): `ParseQuery` (+ fuzz), `UpstreamQuery`
  (ID 0, паддинг до 128), `Reply` (ID и регистр вопроса, старение и ограничение TTL туннеля,
  негативы 60 с, OPT, сначала лишние секции, потом TC), `Synth`, `Negative`, кэш, singleflight,
  клиенты DoH (HTTP/2, заголовки, 200 и тип, редирект, > 64 КиБ, таймаут, повтор после обрыва, без
  прокси окружения), DoT и TCP на loopback, `Resolver` и здоровье (3 ошибки подряд, пробный запрос,
  удвоение паузы до 120 с, что не считается).
- `dnscache`: `AddAnswerFor` принимает только ответ с ID и вопросом своего запроса.
- `divert`: фильтр без DNS байт в байт прежний; с DNS: группа диапазонов, `fragment`, `tcp.SrcPort
  == RELAY`, TCP-only без UDP; компиляция и семантика в `tools/wdfilter` (в CI), в том числе с
  `MaxServerIPs` адресами серверов; число тестов фильтра (`filterTests`) сверяется со счётом WinDivert.
- `sysdns`: `ParseNames`, `Info.Local`; на Windows обход адаптеров без прав администратора
  (`FlushCache` не вызывается, реестр не читается).
- `flows`: закрытые DNS-строки в своём кольце, `Closed` сливает оба по времени закрытия. `stats`:
  DNS-строки и обычные потоки через один сэмплер — считаются только потоки.
- `relay`: режим DNS вызывает `ServeDNS`, его соединение к серверу сбрасывается `Abort`,
  `AbortWhere` сбрасывает только совпавшие.
- `engine` (DNS-политики, синтетические пакеты, поддельный резолвер): без политики пути прежние;
  туннель (ответ от имени сервера, строка `dns`), туннель недоступен и ошибки резолвера — SERVFAIL
  без отправки наружу; имена серверов, служебные и зарегистрированные HyRoute; серверы других
  адаптеров (прямые имена мимо, негатив туннеля — тому серверу, публичный и `100.100.100.100`); свой
  трафик; блок, канарейка, ECH, AAAA; прямой upstream (ошибка и NXDOMAIN — дальше как раньше, NODATA
  только для A); ожидание владельца (поздний, никогда, свой, нет места); агрегация строк и их
  кольцо; временные имена; пауза портала; TCP в relay (`DNSDest`, `Meta`), `ServeDNS` (ответы,
  передача дальше, границы, мусор), маршрут передачи (служба DNS — напрямую, туннель без запасного
  пути, блок); `DropDoH`, `AbortDNS`, блок DoH браузеров, счётчик `SystemDoH`; удержание
  фрагментированного запроса к роутеру; `SysDNSView` (фоновое обновление, интервал, сбой).
- `store`: `dns.json` — отсутствие, round-trip, адрес своего сервера не открытым текстом, мягкий
  разбор, битый файл.
- `app` (DNS): `SaveDNS` (проверка, применение к сессии, сброс кэша при сохранении, подключении,
  отключении, сохранении правил, ограничение частоты, битый файл не перезаписывается, секреты не в
  журнале и диагностике), `Status.DNS`, пауза портала, имена политики, `SetDNS` раньше `SetRules`,
  строка DNS в «Проверить адрес», `OwnDial` регистрирует хосты подписок (и редиректа), баз правил и
  обновлений.
- `stats` ([app.md, «Статистика»](app.md#статистика)): одно соединение на запись, приращения байт,
  надгробия при высокой частоте закрытий, сэмплер без `View` для неизменившихся записей, маршруты
  (`fo` только у tunnel, у отклонённых нет байт), NL6, `reflected…`/`aborted…` не считаются, режимы
  и `mode.json`, смена дня и часы назад, лимиты памяти и 7 дней, запись с обрезкой и суммами,
  битые/новые/будущие файлы, свёртка (повтор после сбоя), периоды отчёта, кэш по байтам, экспорт и
  замена, перенос `traffic.json` версии 1.2 (в том числе с `null`, большой файл за линейное время,
  повтор после свёртки, «Сбросить статистику» до завершения переноса).
- `flows`: `Settled`/`Failed` по всем исходам движка и relay, `Ticks` и `rev`. `engine`: IPv6-блок
  снимает группу и failover. `relay`: `aborted: stopping` без `Rejected`.
- `store`: `StatsFiles` — отсутствующая папка не создаётся чтением, ссылки и жёсткие ссылки
  отклоняются, папка-ссылка отклоняется до чтения, `SweepTemp`.
- `app` (статистика): Disconnect/Reconnect не ждут дисковой блокировки статистики, EndSession не
  ждёт `c.mu`, Shutdown пишет вне `lifeMu`, записи прокси, имена серверов и групп, ничего не
