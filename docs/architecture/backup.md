# Резервная копия

- **Формат** (`internal/backup`, без зависимостей от остального кода). Один файл `.hyroute-backup`:
  конверт JSON `{format: "hyroute-backup", version: 1, encrypted, …}`. С паролем: полезная нагрузка
  — gzip(JSON), AES-256-GCM, ключ Argon2id (t=3, m=64 МиБ, p=4, соль 16 байт;
  `golang.org/x/crypto/argon2`), весь заголовок (`version/cipher/kdf/time/memory/threads/salt`) —
  AAD, поэтому неверный пароль и подмена неотличимы. Границы KDF проверяются до Argon2 (память ≤ 128
  МиБ, работа ≤ 4× по умолчанию), запуски Argon2 идут по одному (`kdfMu`). Файл ≤ 96 МиБ,
  распакованная нагрузка ≤ 64 МиБ. Без пароля нагрузка лежит открыто и не содержит секретов
  (`Encode` отказывает при `secrets: true`). Нагрузка: `app`, `created`, `secrets`, `targets`
  (описания серверов и групп, на которые ссылаются разделы: имя, адрес, порты, имя подписки — без
  секретов) и `sections`. Неизвестные поля верхнего уровня пропускаются (копия новее), разделы
  разбираются строго: неизвестное поле делает непригодным только свой раздел. Файлы `.hyroute`
  версии 1.2 (`kind: full|rules`, PBKDF2-SHA256 → AES-256-GCM, AAD `format/version/kind`) читаются
  (`legacy.go`) и раскладываются по нашим разделам (`legacySections`); копия «Только правила» даёт
  только раздел «Правила» — опции движка и kill switch отправителя не переносятся. Пишется только
  новый формат.
- **Разделы** (`internal/app/backup_sections.go`, таблица `backupSections` — и порядок
  восстановления): Серверы, Подписки (только с паролем), Группы серверов, Правила (правила
  включённого профиля и `rulesets.json`), Прокси, Настройки (опции движка из `settings.json` и
  `prefs.json` без ключей баз, `skipVersion` и `cli` — перечисляются обобщённо, поэтому новые ключи
  других функций переносятся без правки backup), Базы правил, Оформление (тема и акцент WebView).
  Без пароля: пароли серверов пустые, подписок нет, прокси с паролем пропущены, свои ссылки баз,
  свой DNS-сервер и свой адрес проверки групп не пишутся, статистики нет. Экспорт проверяет те же
  пределы, что и восстановление (`importLimits`: 10 000 серверов всего, 100 подписок, 10 000 правил
  на профиль, 64 прокси; `checkLimits`), поэтому копию, которую нельзя восстановить, HyRoute не
  пишет. Сети (`networks.json`: ссылки на профили правил — через карту профилей из копии, затем по
  ID и по имени; не найден — действие правила остаётся без смены профиля, с предупреждением), DNS
  (`dns.json`, только замена; без пароля свой сервер пишется как значение по умолчанию), Статистика
  (только с паролем, по умолчанию не отмечена; независимый раздел:
  `StatsBackupInfo`/`ExportStats`/`CheckStatsImport`/`ReplaceStats` вызываются без блокировок
  контроллера, замена — после записи остального, сбой — предупреждение). Ключ `cli` в `prefs.json`
  не переносится (`prefsNever`, как `skipVersion`): копия не расширяет доступ `hyroutectl`, при
  битом `prefs.json` восстановление пишет `off`.
- **План** (`backup_plan.go`, `planRestore` — чистая функция над снимком `cfgState`). Проверки
  выбора и битых файлов (битый файл заменяет только «Заменить» своего раздела; серверы нельзя
  заменить, пока не загружены `settings.json`, `proxies.json`, `rulesets.json` или `groups.json`),
  затем: ID из файла — только `^[0-9a-f]{8,32}$` (группы `grp-` + 12 hex), иначе новые; имена
  длиннее 200 символов сокращаются; каждый сервер проходит проверку редактора (одиночный плохой
  пропускается с предупреждением); пути `tls.ca` и `tls.ech` (если ECH не встроенный base64,
  `hysteria.ECHInline`) принимаются только как локальные пути с буквой диска фиксированного или
  съёмного диска и ни разу не открываются. Сопоставление серверов — только по полному совпадению
  параметров подключения (`SameConnection`, для серверов без секретов `SameConnectionNoSecrets`):
  только так пароль переходит к серверу из копии; имя и ID сами по себе ничего не дают. Ссылки из
  копии (правила всех профилей, «Всё остальное», запасные, прокси, члены групп, основной)
  разрешаются: карта ID → ID результата → совпадение подключения → по имени и адресу из `targets` →
  по имени (сначала в подписке с тем же именем) → по адресу; иначе ссылка остаётся висящей (отказ,
  не напрямую) с предупреждением. Серверы, на которые ссылается то, что остаётся, не удаляются;
  используемая группа не остаётся без серверов (её последние члены остаются). Каждое изменение опции
  — строка «было → станет», ослабление защиты (kill switch, IPv6, QUIC, DNS через сервер, канал
  beta, «DNS по правилам», «Не давать браузерам обходить DNS») — ещё и предупреждение; правило сети,
  которое отключает HyRoute (и так снимает блокировку kill switch), новое или изменённое, — тоже.
  Тексты плана — `BackupMsg` с чувствительными частями (пути) для Privacy mode; `planDigest` —
  sha256 текстов (ID в них нет).
- **Применение** (`backup.go`, `backup_commit.go`). Статистика проверяется (`CheckStatsImport`) и
  запоминается для отмены (`ExportStats`) до всех блокировок. Порядок блокировок: `importMu` →
  блокировки подписок (текущие и из копии, по возрастанию, с повтором, если подписка появилась) →
  `prefsMu` (ни один `UpdatePrefs` не запишет прежний `prefs.json` поверх восстановленного) →
  `saveMu` → `mu`. Под ними план считается заново: другой `digest` — `ErrPlanChanged`, ничего не
  пишется. Сырые байты всех файлов, которые запишутся (и `rulesets.json` вместе с `settings.json`),
  запечатываются DPAPI в `restore-undo.sealed`; затем копии битых файлов
  (`<file>.broken-YYYYMMDD-HHMMSS`) и запись в порядке `subscriptions → profiles → groups → proxies
  → settings(+rulesets парой) → networks → dns → prefs` функциями `Store`, не `save*Locked`. Сбой —
  все записанные файлы возвращаются байт в байт (`WriteRaw`), копии битых удаляются, прежняя запись
  отмены восстанавливается. Установка в память без ввода-вывода (`netInstallLocked` ничего не делает
  сразу, `dnsInstallLocked` передаёт политику DNS работающему сеансу; её ошибка — предупреждение),
  ревизия настроек растёт, `rulesAt` двигается, если изменились правила (B8); после блокировок —
  прокси, kill switch, журналы, базы (`pokeGeo`), очистка кэша DNS Windows (один раз: «backup», если
  записан `dns.json` при подключении, иначе «rules», если записаны правила при включённом «DNS по
  правилам»), `ReplaceStats`, `clearConnUndo` (если записаны правила), `OnSettings`; окно после
  вызова переприменяет режим `hyroutectl`, если он изменился. Подписки из копии обновляются в фоне
  как часть восстановления: `applyFetched` с меткой восстановления сдвигает хэш `after`, если файл
  никто больше не менял, поэтому «вы меняли…» точен.
- **Отмена** («Вернуть как было»): байты из записи возвращаются в файлы, файлы перечитываются теми
  же загрузчиками, что и при запуске (`Load` разделён на `loadFile` и `installLoadedLocked`, в том
  числе `dns.json` и `networks.json`), так что битый до восстановления файл снова битый; статистика
  до восстановления, если она была в записи, возвращается `ReplaceStats`. Снимки подписок, которые
  восстановление удалило, живут, пока есть отмена. «Забыть» удаляет запись.
- **Файл пользователя** (`store.WriteUserFile`/`ReadUserFile`). HyRoute работает с правами
  администратора, поэтому пишет и читает выбранный путь только так, как мог бы сам пользователь:
  папка открыта и проверена `AccessCheck` ограниченным токеном, временный файл создаётся
  `NtCreateFile` относительно хэндла папки (владелец — пользователь) и переименовывается поверх цели
  относительно того же хэндла, ссылка на месте цели заменяется, а не проходится; чтение — с
  `SECURITY_IDENTIFICATION` и проверкой доступа на открытом хэндле. Сетевые пути решаются по
  открытому хэндлу: общие папки этого компьютера (localhost, свои имена и адреса, том с серийным
  номером локального диска) и скрытые «$» отклоняются, настоящую сетевую папку проверяет сервер.
