# Сети

«Сети» (`internal/netmode`, `internal/netwatch`, `internal/app/netmodes.go`, файл `networks.json`) —
упорядоченный список правил сетей: условия на сеть, через которую идёт маршрут по умолчанию, и
действие (подключить / отключить / переключить профиль правил / ничего), плюс действие «Неизвестная
сеть» (по умолчанию «Подключить»). Пока функция выключена, ничего не читается: нет наблюдателя, нет
COM-потока, нет снимка при запуске (кроме одного чтения при открытии страницы и по «Обновить»).

- **Активная сеть** — интерфейс лучшего маршрута к 1.1.1.1, иначе к 2606:4700:4700::1111
  (`GetBestInterfaceEx`, пакеты не отправляются). Остальные подключённые сети показываются, но не
  сравниваются.
- **Чтение** (`netwatch.Snapshot`): `GetAdaptersAddresses` (с шлюзами); шлюз — наименьший IPv4,
  иначе наименьший IPv6; его MAC — из таблицы соседей (`GetIpNetEntry2`, без ARP/ND). NLM
  (`INetworkListManager` через vtable) работает на отдельном потоке COM: ленивый старт, 3 с на вызов
  (отсчёт — с момента, когда поток принял запрос; ожидание очереди за чужим вызовом поток не
  бросает), зависший поток бросается, после 3 брошенных NLM «не отвечает» до перезапуска, выход
  после минуты простоя; всего чтение NLM ждёт не больше 6 с (очередь + ответ), реестр, таблица
  соседей и WLAN отвечают сразу. ID сети считается **опознанным** (`Identified`), только если сеть
  доменная или в `HKLM\...\NetworkList\Signatures\{Unmanaged,Managed}` есть подпись с этим
  `ProfileGuid` (только чтение). Имя Wi-Fi — `WlanQueryInterface(current_connection)` только для
  адаптера активной сети и только когда нужно (правило с именем Wi-Fi, «Текущее», свежее чтение
  страницы): в Windows 11 это доступ к расположению. Уведомления: `NotifyIpInterfaceChange`,
  `NotifyUnicastIpAddressChange`, `NotifyRouteChange2` через один общий `NewCallback`, который
  только неблокирующе шлёт в канал.
- **Идентичность и смена** (`netmode.Ident`, `Compare`): ID сети NLM (только опознанной) и — только
  для обнаружения смены, никогда для совпадения и показа — GUID адаптера, IP и MAC шлюза. Категория,
  имя Wi-Fi, разрешение на него и имя сети в идентичность не входят: их смена — не смена сети.
  Отношение чтения к базовой сети: Same (тот же ID; без ID — тот же адаптер и IP шлюза и оба MAC
  известны и равны), Refined (у базы не было ID, у чтения есть, та же связь), Unclear (без ID, та же
  связь, MAC неизвестен с одной из сторон), Changed (всё остальное). База дополняет пустые IP/MAC
  только из Same и Refined. Пропажа сети — не смена и базу не сбрасывает.
- **Асимметричное решение.** Первое чтение новой сети (фиксированно через 2 с после первого события
  пачки; каждые 2 с, пока что-то ждёт; раз в 30 с без уведомлений) сразу выполняет защитную часть
  (`netmode.Protective`): подключение, если решение «Подключить» или ID ещё нет и «Неизвестная сеть»
  подключает; профиль «Неизвестной сети» вместо профиля, включённого правилом сети. Всё, что
  ослабляет защиту (отключение, профиль совпавшего правила), ждёт второго чтения той же сети с ID
  через 2 с или 15 с без ID. Unclear перечитывается; если через 15 с так и неясно и «Неизвестная
  сеть» что-то изменила бы, это смена. Сеть, решённая без ID, решается заново, когда Windows её
  опознает (если пользователь не вмешался). Ожидающая сеть, получившая ID, остаётся той же ожидающей
  сетью (действие пользователя не сбрасывается, защитная часть не повторяется), но ослабляющая часть
  ждёт ещё одного чтения с этим ID через 2 с; ID базовой сети на новой связи так не считается
  (решает сравнение с базой).
- **Имя Wi-Fi** запрашивается один раз на идентичность и кэшируется только для неё: для чтения той
  же сети (Same, Refined) или ожидающей сети, для которой запрошено. Чтение, которое может быть
  другой сетью (Unclear, Changed), кэш не берёт: первое чтение новой сети спрашивает имя заново.
  Кэшируется только ответ (имя или отказ Windows); после ошибки запроса имя спрашивается снова при
  подтверждении.
- **Ручное действие побеждает** до следующей смены сети:
  `Connect`/`Disconnect`/`Reconnect`/`ReleaseKillSwitch` и переключение профиля пользователем
  вызывают `netManual` (поколение +1, override) до своих блокировок. Автоматическое действие
  запоминает поколение и ревизию настроек (`rev`, её меняет каждая установка конфигурации:
  сохранение, включение/выключение, перечитывание, восстановление) и пропускается, если сменилось
  одно из них или функция выключена; уже идущее действие (под `netActMu`) заканчивается, и действие
  пользователя идёт после него.
- **Запуск** (`planStart` в `cmd/hyroute/startgate.go`): обычный запуск — защитная часть правила опознанной сети
  сразу, ослабляющая — после подтверждающего чтения; без опознанной сети — «Подключаться сразу после
  запуска», а первая сеть — смена (или база с override, если пользователь уже что-то сделал).
  Обновление, откат и перенос восстанавливают прежнее состояние и ничего не делают: первая сеть —
  база с override. `startGate` ждёт решения при запуске и окна и только потом показывает окно, если
  блокировка kill switch осталась, а подключения нет (с выключенными «Сетями» окно при такой
  блокировке показывается сразу, как раньше).
- **Выход, обновление, перенос:** `StopNetModes` до `routingOn` и `HoldKillSwitch`;
  `ResumeNetModes`, если новая копия не запустилась.
- **Блокировки.** `netActMu` → `saveMu` → `mu` → `netMu` и `netActMu` → `lifeMu` →
  `mu`/`ksMu`/`proxyMu`/`recMu` → `netMu`. `netActMu` держится всё время `netApply` и коротко в
  `netManual`/`StopNetModes`/`ApplyNetModes` (отпускается до `netApply`); `netMu` — самая
  внутренняя. Чтения Windows — вне всех блокировок.
- **Файл.** `networks.json` (версия 1, строгий разбор, лимиты: 1 МБ, 100 правил, 32 значения в
  условии). Повреждённый файл не перезаписывается, правила не действуют, ошибка — в общей плашке и
  на странице; пользователь исправляет или удаляет файл или заменяет его из резервной копии («Сети»
  → «Заменить», [backup.md](backup.md); `.hyroute` v1.2.0 его не содержит). Имена правил, «Именно
  эта сеть» и имён сетей — без управляющих символов и разделителей строк. `Load` (и «Вернуть как
  было» после восстановления копии) ставит конфигурацию тем же путём, что сохранение
  (`netInstallLoadedLocked`): цикл будит, включение сбрасывает базу, правилам без ID из файла
  возвращаются прежние ID по имени. Сохранение и включение никогда не действуют: включение берёт
  текущую сеть базой.
- **Контракт для hyroutectl и страницы.** Флаг `enabled` меняет только `SetNetModesEnabled(on)`;
  `SaveNetModes` его игнорирует (сохраняет правила и «Неизвестную сеть»), так что «networks on|off»
  в CLI — это `SetNetModesEnabled`, не `SaveNetModes` с `Enabled`.
  `ApplyNetModes(confirmDisconnect)` решает по свежему чтению; правило, которое отключает,
  действует, только если `confirmDisconnect` — его ключ (`NetRuleKey`: ID правила или `unknown`),
  иначе ничего не делается и возвращается вид с `confirm` и `match` этого чтения — спросить и
  вызвать снова. `NetModes(refresh)` — вид страницы (`false` — последнее чтение цикла без вызовов
  Windows).
- **Приватность.** Имена сетей, Wi-Fi, ID сетей, GUID адаптеров и адреса шлюзов не попадают в
  журнал, диагностику и `Status` (поля шлюза — `json:"-"`); в журнале — только имена правил, вид
  подключения и тип сети, в отладочном — `Ident.Hash8()`. В окне имена сетей и правил скрывает
  `hideNet`, тексты — `netText`/`hide`; для hyroutectl —
  `NetModesView.Private()`/`NetState.Private()`; в диагностике с «Скрыть данные» имена правил и
  тексты последнего действия маскируются так же.
- **Безопасность.** `networks.json` лежит в папке данных, которую может править пользователь, а
  читает его процесс с правами администратора: разбор строгий (лимит размера, неизвестные поля —
  ошибка, лимиты числа правил и значений, проверка ID, GUID, имён и действий), а всё, что файл может
  вызвать, — подключить, отключить и переключить профиль правил на существующий; ни путей, ни
  команд, ни адресов в нём нет. Остаточный риск — поддельная точка доступа: имя Wi-Fi, имя сети и
  тип подделать легко, поэтому для «Отключить» страница советует «Именно эта сеть» или «Доменную»;
  для неуправляемой сети Windows опознаёт сеть по MAC шлюза, и подделавший этот MAC злоумышленник в
  той же сети может выдать себя за доверенную сеть — тогда правило «Отключить» сработает, и трафик
  пойдёт напрямую (как без HyRoute).
- **Отказ в сторону защиты.** Всё неопознанное — «Неизвестная сеть»; ослабить защиту может только
  положительное совпадение с опознанной сетью. Остаётся окно после отключения по правилу: новая сеть
  защищена с первого решающего чтения (обычно 2–3 с; до ≈15 с при том же IP шлюза без ID и MAC; до
  30 с без уведомлений).
- **Допущения о Windows.** Опознание сети опирается на то, что `INetwork::GetNetworkId` совпадает с
  `ProfileGuid` подписи, а у «Идентификация…» и «Неопознанной сети» подписи нет; индексы vtable
  взяты из `netlistmgr.h`. Это проверяют смоук-тесты `internal/netwatch`, которые запускаются только
  с `HYROUTE_NETWATCH_SMOKE=1`: `TestIdentitySmoke` проверяет, что ID активной сети NLM — GUID
  профиля в `NetworkList\Profiles`, а с `HYROUTE_NETWATCH_EXPECT=identified` (обычная домашняя сеть)
  или `=unidentified` («Неопознанная сеть») — опознана ли сеть. Если `ProfileGuid` окажется не равен
  ID сети NLM, опознание (`Identified`) нужно переделать.
