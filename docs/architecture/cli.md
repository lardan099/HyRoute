# Командная строка (hyroutectl)

`hyroutectl.exe` (`cmd/hyroutectl`, консольная подсистема, манифест `asInvoker`) управляет уже
запущенным HyRoute. Он не импортирует `internal/app`: вся логика клиента (аргументы, декодирование
файлов, поиск HyRoute, обмен, вывод) — в `internal/ctl/cli`, протокол и транспорт — в
`internal/ctl`, диспетчер команд внутри HyRoute — в `internal/ctl/ctlserver`, связка с GUI и
контроллером — `cmd/hyroute/ctl_windows.go`. Всё, что делает CLI, делает и окно: каждая команда вызывает тот же
метод контроллера, что и кнопка.

- **Канал.** Именованный канал `\\.\pipe\HyRoute-7f3c1a52-ctl-<SID владельца>`, байтовый режим, один
  запрос на соединение, кадры «длина uint32 big-endian + JSON». Владелец — интерактивный
  пользователь сеанса HyRoute (`WTSQuerySessionInformation`; при over-the-shoulder UAC это не
  учётная запись, под которой HyRoute работает). SD:
  `O:BAG:BAD:P(A;;GA;;;SY)(A;;GA;;;BA)(A;;RC;;;OW)(A;;0x12019b;;;<владелец>)[(A;;0x12019b;;;<учётная
  запись HyRoute>)]S:(ML;;NW;;;ME)`: у пользователя нет `FILE_CREATE_PIPE_INSTANCE`, права владельца
  объекта нейтрализованы `OW`, процессы низкой целостности не пишут. Первый экземпляр с
  `FILE_FLAG_FIRST_PIPE_INSTANCE` (имя занято — `ErrNameTaken`, повтор каждые 30 с),
  `PIPE_REJECT_REMOTE_CLIENTS`, до 8 экземпляров; владелец каждого нового экземпляра проверяется.
- **Кто может.** Сервер определяет клиента имперсонацией уровня identification на отдельном
  заблокированном потоке (`ImpersonateNamedPipeClient` → `OpenThreadToken` → `RevertToSelf`; не
  вернулся — поток не разблокируется и умирает с горутиной). Пускаются: владелец, учётная запись
  HyRoute, SYSTEM, повышенный администратор; целостность не ниже medium. Сеанс не проверяется (та же
  учётная запись по SSH или из Планировщика — тоже она). Отказ — кадр `denied`, а не обрыв.
- **Клиент.** `CreateFile` с `SECURITY_SQOS_PRESENT|SECURITY_IDENTIFICATION`, затем проверка
  владельца канала: только Administrators или SYSTEM (объект с таким владельцем программа без прав
  администратора создать не может), иначе ничего не отправляется. Подключённые концы — `*os.File` из
  `os.NewFile` на overlapped-хэндле (IOCP рантайма, дедлайны, `Close` отменяет ввод-вывод); свой
  overlapped-код только у `ConnectNamedPipe` до передачи хэндла рантайму.
- **Событие запуска.** `Global\HyRoute-7f3c1a52-run-<SID владельца>` (владелец Administrators,
  пользователю — `SYNCHRONIZE|READ_CONTROL`) создаётся сразу после захвата экземпляра, сигналится,
  когда канал поднят, выключен или не создался, и закрывается при выходе. Нет канала, событие не
  сигнальное — «HyRoute запускается», команды ждут; сигнальное — «не принимает команды»; нет события
  — «не запущен».
- **Протокол.** Сервер начинает `hello{app, proto, minProto, mode}` (или `denied`, или `off`);
  клиент вне `[minProto, proto]` ничего не отправляет и говорит, что обновить. Запрос `{v, cmd,
  args, private}`, аргументы разбираются строго: неизвестное поле — `unknown-arg` (код выхода 7).
  Ответ — ноль или больше кадров `event` (страницы журнала до 500 записей) и один `final`; `subs
  update` без имени шлёт пустой не финальный кадр после каждой подписки. Время ответа клиент
  отсчитывает заново с каждого не финального кадра: лимит — на шаг, не на всю команду. Размеры:
  запрос до 4 МиБ (проверяется до выделения памяти, превышение — ответ `usage`), файл правил до 1
  МиБ, ответ до 16 МиБ. Запросы и ответы кодируются без HTML-экранирования; `--json` клиента
  перекодирует вывод в ASCII (`\uXXXX`).
- **Режимы.** `prefs.json` ключ `cli`: нет ключа — «Только просмотр» (по умолчанию), `full` —
  «Полный доступ», `off` — канала нет. Неизвестное значение и битый `prefs.json` читаются как `off`
  (`Controller.CLIMode()`): значения по умолчанию доступ не расширяют. Режим перечитывается на
  каждый запрос; мутирующая команда в «Только просмотр» получает `read-only`. Все записи
  `prefs.json` идут через `Controller.UpdatePrefs` под `prefsMu` (порядок блокировок: `prefsMu` →
  `mu`); восстановление резервной копии и его отмена держат `prefsMu` вокруг своих записей (после
  блокировок подписок: `prefsMu` → `saveMu` → `mu`), а режим `cli` не переносится
  ([backup.md](backup.md)).
- **Ход запроса.** Нет блокировок CLI поверх контроллера: команды упорядочивают его собственные
  блокировки, как одновременные клики. Горутина-наблюдатель читает соединение: клиент ушёл до
  мутирующего вызова — вызов не делается; начатый доводится до конца. Паника обработчика — ошибка
  `failed`, сервер работает дальше. Каждый кадр пишется с дедлайном 30 с (поток `logs --follow`,
  который никто не читает, заканчивается), запрос ждётся 10 с; после финального кадра сервер ждёт,
  пока клиент закроет соединение (до 2 с), и только потом закрывает своё (без `DisconnectNamedPipe`,
  который выбросил бы непрочитанный хвост).
- **Выход.** `Controller.BeginExit` (из `Shutdown`, установки обновления и переноса в Program Files,
  до их проверки «было ли подключение») запрещает `Connect`/`Reconnect` («HyRoute завершает
  работу»), так что подключение из CLI, трея или по правилу сети не начнётся в последние 200 мс;
  подключения «Сетей» (`netConnectLocked`, `ConnectAtStart`) при `closing` ничего не делают.
  `stopCLI` — первым делом в `OnShutdown`.
- **Команды других функций.** `networks` — `NetModes(true)` (свежее чтение сети); `networks on|off`
  — `SetNetModesEnabled` (только флаг, ничего не применяет); `networks apply` — `ApplyNetModes("")`,
  а правило, которое отключает HyRoute (и снимает блокировку kill switch), выполняется только с
  `--yes`: ключ правила берётся из ответа с `confirm` и передаётся вторым вызовом, как после диалога
  в окне. `stats [период]` — `stats.Report` как есть. `explain` отдаёт `Explanation` с именем
  сервера в строке DNS (`dns.profileName`: клиент ID не разрешает). В `status` — `net` (`NetState`)
  и `dns` (`DNSStatus`); счётчики `dns*` — в `stats`. Клиент читает всё это «лёгкими» структурами
  (`cli.*Lite`), `TestLiteContract` сверяет их с настоящими типами.
- **Правила JSON.** `{"hyroute":"rules","version":1,"defaultAction",…,"rules":[…как в
  settings.json…],"targets":{id:{name,group}}}` (`internal/app/rulesjson.go`). Экспорт называет
  каждую цель; импорт находит чужие ID по точному имени, свою удалённую цель (`name: ""`) оставляет
  с предупреждением (движок отклоняет такие соединения), каждое правило компилирует отдельно,
  повторные ID сбрасывает. «Правила текстом» понимают JSON автоматически (`{` первым символом).
- **Секреты и приватность.** DTO канала — белые списки: пароли, obfs, пины, ссылки подписок, пароли
  прокси, свои адреса DNS и пробы через канал не ходят. `--private` пропускает каждую строку ответа
  через `SanitizeFunc` (как экспорт журнала); имена сетей, Wi-Fi и правил сетей в `networks` и
  `status` сначала заменяются на «***» (`NetModesView.Private`, `NetState.Private`). В журнал движка
  пишутся мутирующие команды без содержимого файлов, путей и адресов из `explain`.
